Meeting & Reporting Workflow

An end-to-end reporting automation for a McDonald's franchise organization that turns raw weekly performance data and meeting transcriptions into a presentation-ready deck, with no manual work.

View on GitHub ↗

Problem

Leadership spent 3–4 hours every week pulling store-level metrics, building charts, and writing up meeting notes by hand.

Architecture

The pipeline pulls metrics for each restaurant location across seven categories (breakfast, lunch, dinner, labor, food, digital, and voice), generates 16 charts, and assembles them into a formatted presentation using live data references. The same workflow transcribes leadership meetings and sends the summaries to a database.

Google Drive→AssemblyAI→Claude Sonnet 4.6→Google Sheets→QuickChart API→Gamma→Notion

Result

With senior leadership's approval, the system cut a 3–4 hour weekly manual process to about 3 minutes. End-to-end testing produced a complete 16-chart weekly deck from real store-level data.

My role

Led idea creation, marketing research, coding translation between the technical and non-technical sides of the team, and the final pitch to judges.

Problem

Residents living with memory loss grew up singing hymns, but today's Bible apps have small text, busy screens, sign-ins, and streaks. The aide who would sit with them has minutes, not time to prepare a devotion.

Architecture

A static iPad app on Cloudflare Pages reads published content from Supabase (Postgres with row-level security). Scripture is fetched live from the YouVersion API through an edge function, and Gloo AI curates, but never writes, religious content.

Gloo AI Studio→Supabase→Cloudflare Pages→YouVersion API

Result

Finished top 10 at the Gloo AI Hackathon 2026. Passes WCAG 2.2 AA accessibility checks and runs at zero hosting cost. Built with teammates JP Clark and Clark Cully.

NBA Player Consistency Model

An automated predictive analytics system that measures how consistently NBA players perform, so their outcomes can be predicted more reliably.

Problem

Raw box scores say what a player did, not how reliably they do it. Daily stat tracking was manual and inconsistent.

Architecture

A scheduled daily pipeline (daily_ingestion.py, orchestrated by a daily_run.yml workflow) pulls fresh game data, runs it through a Python scoring engine (consistency_model.py) using rolling coefficient of variation, standard deviation, and weighted averages, and stores ranked results in a Supabase database.

Game data→daily_ingestion.py→consistency_model.py→Supabase

Process

Version-controlled on GitHub and built in VS Code. Used Claude Code to run a full codebase audit for inefficiencies in the calculations and the data flow.
